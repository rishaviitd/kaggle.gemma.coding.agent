Official outcomes

Resolution is the evaluator outcome. Harness completion, a captured patch, and a test result answer different questions. Each rate uses known outcomes and shows coverage.

Wilson intervals describe uncertainty around observed proportions; repository sample sizes differ. These are attempts, not necessarily unique tasks.

From source change to verification

These are independent indicators with different denominators. They are not a sequential funnel: a patch can be captured without a confirmed edit tool, and a recorded test can fail.

Budget pressure and submission loops

Budget stage uses observed rejections or authoritative call limits. Raw submit attempts can far exceed budget-counted calls; an accepted submit_patch response is not a separate resolved task.

Tool reliability

Execution status describes whether a tool ran. It does not say whether a test passed or a patch fixed the issue. Missing results remain unknown. Submission calls have their own chart because their volume would hide other tools.

Where unresolved attempts appear to stall

Primary stages are tentative rule labels selected from observable evidence. They do not establish the semantic root cause. Click a task in the index to inspect the full trace.

Time, calls, and reported inference tokens

Duration comes from the final harness result. Budgeted calls, raw tool attempts, and model calls differ. Token totals are summed per turn and include repeated prompt context.

Repeated findings and candidate actions

Counts are affected attempts, not event counts. Suggested actions are hypotheses to test. Tool errors from a deliberately failing reproduction are kept separate from actual edit failures.

Data quality and interpretation limits

Missing tool results, conflicting budget instructions, and token-total mismatches are visible rather than silently repaired. Optional gold-function recall and paired outcome changes require additional inputs.

Optional gold and paired analyses

Gold-function recall requires reference patches and a reliable baseline symbol map. Paired outcomes require a second batch with unique task mapping. Unavailable values are shown with reasons.
